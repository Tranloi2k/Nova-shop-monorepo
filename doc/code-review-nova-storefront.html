1. Đánh giá tổng quan

ĐIỂM TỐT Khá ấn tượng cho dự án cá nhân

  • Tách bạch rõ server services ("use server" trong app/lib/services/*) và client components — kiến trúc App Router đúng chuẩn.
  • Hệ thống cache tags (cache-tags.ts), revalidate-shop, seo được modular hóa tốt — tư duy caching/ISR & SEO vượt mức "dự án cá nhân".
  • Dùng useSyncExternalStore cho cart badge thay vì useState+useEffect — đúng cách, tránh hydration mismatch.
  • Token refresh tự động trong authFetch (retry 401) gọn gàng; fallback public catalog khi 401 là quyết định tốt.
  • Defensive coding tốt: getSafeImageUrl, getProductStock, EMPTY_RESULT, isNextNavigationError (rất quan trọng — tránh nuốt nhầm lỗi redirect()/notFound()).

CẦN CẢI THIỆN Xếp theo mức độ ưu tiên

  • BUG Mất search term khi redirect out-of-bounds (page.tsx dùng sai key q).
  • KIẾN TRÚC State cart phân mảnh qua 3 cơ chế độc lập → dễ desync.
  • MAINTAIN Format tiền có 4 implementation, 2 cái cho output khác nhau (có/không cents) → hiển thị giá không nhất quán.
  • A11Y Cart Drawer không accessible (không phải dialog thật, không trap focus, không Esc) + nesting HTML không hợp lệ <button><a></a></button>.
  • DRY Trùng lặp logic Product Card ở 3 nơi (vi phạm DRY/SRP).
  • PERF force-dynamic vô hiệu hóa toàn bộ caching mà chính bạn đã thiết kế.
  • SECURITY resolveUserId decode JWT không verify + truyền userId qua query string → nguy cơ IDOR.

2. Nhận xét chi tiết + Technical Why

🔴 BUG 2.1 — Mất query khi redirect page.tsx:139–146

// app/(shop)/products/page.tsx:142
if (filters.query) params.set("q", filters.query);   // ❌ key "q"
Technical why: parseProductFilters chỉ đọc params.query (product-filters.ts:54), và Search cũng params.set("query", ...). Khi user vào ?query=iphone&page=99 (out of bounds), redirect sinh ra ?q=iphone → vòng sau parse ra query = "" → mất từ khóa tìm kiếm; category/sort được giữ nhưng query thì không. Dễ lọt qua test thủ công vì hiếm khi test page out-of-bounds.
Fix đề xuất
if (filters.query) params.set("query", filters.query);

// Tốt hơn: tái dùng productsHref() đã có sẵn thay vì build URLSearchParams lần thứ 3
if (result.products.length === 0 && filters.page > 1) {
  redirect(productsHref({
    category: filters.category,
    query: filters.query,
    sort: filters.sort !== "popular" ? filters.sort : undefined,
  }));
}

🔴 KIẾN TRÚC 2.2 — State cart phân mảnh (3 nguồn sự thật)

  • cart-events.ts: localStorage + CustomEvent → chỉ giữ count cho badge.
  • cart-drawer-context.tsx: context chỉ giữ isOpen (không giữ dữ liệu cart).
  • Mỗi component tự getCartSummary(): NovaHeader (header.tsx:68), NovaCartDrawer (drawer.tsx:64), CartView giữ state riêng.
Technical why: Vi phạm Single Source of Truth. Hệ quả: mở drawer fetch lại cart mỗi lần dù header vừa fetch; badge count (localStorage) và nội dung drawer (summary cục bộ) có thể desync; CartView cập nhật xong → badge đúng nhưng drawer đang mount không biết, giữ summary cũ tới lần mở kế tiếp.
Đề xuất — nâng context thành nguồn sự thật cho cả dữ liệu cart
// app/ui/nova/cart-context.tsx
"use client";
import { createContext, useContext, useState, useCallback } from "react";
import { getCartSummary } from "@/app/lib/services/cart";
import { syncCartBadge } from "@/app/lib/cart-events";
import type { CartSummary } from "@/app/lib/definitions";

const Ctx = createContext<CartCtx | null>(null);

export function CartProvider({ children }: { children: React.ReactNode }) {
  const [summary, setSummary] = useState<CartSummary | null>(null);
  const [isOpen, setIsOpen] = useState(false);
  const [loading, setLoading] = useState(false);

  const applySummary = useCallback((s: CartSummary) => {
    setSummary(s);
    syncCartBadge(s.cart?.quantity ?? 0); // badge + nội dung luôn cùng 1 nguồn
  }, []);

  const refresh = useCallback(async () => {
    setLoading(true);
    try { applySummary(await getCartSummary()); }
    catch { setSummary(null); }
    finally { setLoading(false); }
  }, [applySummary]);

  const open = useCallback(() => { setIsOpen(true); void refresh(); }, [refresh]);
  // ...close/toggle
  return <Ctx.Provider value={{ summary, isOpen, loading, open, /* ... */ applySummary }}>{children}</Ctx.Provider>;
}

export function useCart() {
  const ctx = useContext(Ctx);
  if (!ctx) throw new Error("useCart must be used within CartProvider"); // phát hiện sớm
  return ctx;
}

Với scale cá nhân không cần Redux — context + reducer là đủ; hoặc SWR/React Query nếu muốn cache + revalidation chuẩn. Default context hiện trả no-op () => {} (cart-drawer-context.tsx:12–17); dùng null + throw giúp phát hiện sớm khi nằm ngoài Provider.

🟠 MAINTAIN 2.3 — Format tiền: 4 implementation, output khác nhau

NơiCách làmOutput cho 1999
nova-utils.ts formatMoney"$" + n.toLocaleString()$1,999 (không cents)
cart-view.tsx formatPriceIntl.NumberFormat currency$1,999.00
productForm.tsx fmtIntl.NumberFormat currency$1,999.00
utils.ts formatCurrency(amount/100).toLocaleString()$19.99 (chia 100)
Technical why: Product card (formatMoney) và trang cart (formatPrice) hiển thị cùng sản phẩm với 2 định dạng khác nhau ($1,999 vs $1,999.00) — người dùng nhạy cảm với điều này trên trang tiền. formatCurrency lại chia 100; nếu dùng nhầm sẽ ra giá sai 100 lần. Cùng một concept, nhiều nguồn, semantics mâu thuẫn = maintainability hazard kinh điển.
Đề xuất — một hàm duy nhất, khởi tạo Intl một lần ở module scope
// app/lib/format.ts
const usd = new Intl.NumberFormat("en-US", {
  style: "currency",
  currency: "USD",
});
export const formatMoney = (n: number) => usd.format(n);

Intl.NumberFormat constructor khá nặng — tái dùng instance ở module scope thay vì tạo mới mỗi lần gọi trong formatPrice/fmt.

🟠 A11Y 2.4 — Cart Drawer: accessibility & HTML không hợp lệ nova-cart-drawer.tsx

(a) Nesting <button> chứa <a> (dòng 104–112)
<button className="btn btn-dark" onClick={close}>
  <Link href="/products" onClick={close}>Start shopping</Link>   // ❌ button > a
</button>

HTML cấm interactive element lồng nhau → invalid DOM, 2 lần focusable, screen reader đọc nhập nhằng, có thể warning hydration. Dùng Link được style như button:

<Link href="/products" className="btn btn-dark" onClick={close} style={{ marginTop: 8 }}>
  Start shopping
</Link>
(b) Không phải dialog thật (dòng 75–80)
  • Không role="dialog" + aria-modal="true".
  • Không focus trap → Tab thoát ra ngoài drawer.
  • Không đóng bằng Escape.
  • Không scroll lock body (ngược lại, mobile menu trong header.tsx:49–56 có lock — không nhất quán).
Technical why: Drawer là modal overlay → theo WAI-ARIA Dialog pattern phải quản lý focus & cho phép Esc, nếu không người dùng bàn phím/screen reader bị kẹt hoặc lạc focus.
Đề xuất (rút gọn)
useEffect(() => {
  if (!isOpen) return;
  const onKey = (e: KeyboardEvent) => e.key === "Escape" && close();
  const prev = document.body.style.overflow;
  document.body.style.overflow = "hidden";          // scroll lock
  document.addEventListener("keydown", onKey);
  return () => {
    document.body.style.overflow = prev;
    document.removeEventListener("keydown", onKey);
  };
}, [isOpen, close]);

<aside
  className={`drawer${isOpen ? " open" : ""}`}
  role="dialog"
  aria-modal="true"
  aria-label="Shopping bag"
  onClick={(e) => e.stopPropagation()}
>

Cộng thêm: focus vào nút Close khi mở, inert/aria-hidden cho nền. Hoặc dùng <dialog> native + showModal() để có focus trap miễn phí (modern standard 2026).

🟠 DRY/SRP 2.5 — Trùng lặp Product Card

Logic này xuất hiện 3 lần gần như y hệt:

const hasDiscount = (p.discount ?? 0) > 0;
const originalPrice = hasDiscount ? Math.round(p.price / (1 - (p.discount ?? 0) / 100)) : undefined;
const outOfStock = isOutOfStock(p.stock);
  • nova-product-card.tsx:38–43
  • listProductsComponent.tsx:18–23 (grid ProductCard)
  • listProductsComponent.tsx:115–121 (list variant, inline trong .map)

Và productHref/productPath được định nghĩa lại ở nova-product-card.tsx:24, cart-view.tsx:31, và lib/product-path.ts.

Technical why: Mỗi khi đổi công thức giá gốc hay rule slug, phải sửa 3+ chỗ — đúng định nghĩa tech debt. Math.round cho originalPrice có thể lệch 1$ so với giá gốc thực → nên về 1 nguồn để dễ kiểm soát.
Đề xuất — tách "model hóa" thành hàm thuần (dễ test) + presentational card dùng chung
// app/lib/product-view-model.ts
export function toProductCardModel(p: { price: number; discount?: number; stock?: number | null }) {
  const discount = p.discount ?? 0;
  const hasDiscount = discount > 0;
  return {
    outOfStock: isOutOfStock(p.stock),
    hasDiscount,
    originalPrice: hasDiscount ? Math.round(p.price / (1 - discount / 100)) : undefined,
  };
}

Mọi card import hàm này; productPath dùng duy nhất từ lib/product-path.ts. List-variant nên tách thành ProductListRow component thay vì inline JSX dài (listProductsComponent.tsx:122–188) — dễ đọc + cho phép React.memo.

🟡 PERF 2.6 — force-dynamic vô hiệu hóa caching đã thiết kế page.tsx:17–18

export const dynamic = "force-dynamic";
export const fetchCache = "default-no-store";
Technical why: Nhưng getProducts lại set next: { tags, revalidate: 60 } (products.ts:55). force-dynamic + default-no-store ép mọi request render lại và bỏ qua data cache → revalidate: 60 và tag-based revalidation cho catalog công khai trở nên vô nghĩa. Catalog là dữ liệu public, ít thay đổi — đây là phần đáng cache nhất cho Critical Rendering Path/TTFB.
Đề xuất

Bỏ force-dynamic cho catalog public, dựa vào revalidateTag(CACHE_TAGS.catalog) (đã có trong revalidate-shop). Chỉ dùng dynamic cho route thực sự per-user (cart, account). Nếu cần personalization theo auth, tách phần authenticated ra component riêng bọc Suspense thay vì ép cả trang dynamic.

🟡 SECURITY 2.7 — resolveUserId + userId qua query string

auth-tokens.ts:201–215 decode JWT payload không verify chữ ký, rồi cart.ts:60:

return authFetch(`${apiUrl}/cart?userId=${userId}`, ...)
Technical why: Nếu backend NestJS tin vào userId trong query (thay vì lấy từ token đã verify), client có thể đổi userId để đọc cart người khác → IDOR. Decode không verify ở frontend để build cache tag thì chấp nhận được (chỉ dùng nội bộ), nhưng không nên truyền userId lên API như tham số tin cậy.
Đề xuất

Bỏ ?userId= khỏi request; để Nest đọc req.user từ JWT guard. Giữ resolveUserId chỉ cho mục đích cache tag phía Next, và comment rõ "không dùng cho authz".

🟡 NHỎ 2.8 — Các điểm nhỏ (gộp)

  • Import nằm giữa file actions.ts:64 (sau các hàm). Hoạt động được nhưng phá convention; gom hết import lên đầu.
  • confirm() native cart-view.tsx:111 trong khi đã có app/ui/shop/confirm-modal.tsx. confirm() block main thread & lệch UX. Dùng ConfirmModal.
  • search.tsx không bọc <form> — Enter xử lý thủ công (onKeyDown). Bọc <form onSubmit> semantic hơn (submit Enter native, trợ năng tốt hơn).
  • Inline style objects dày đặc (style={{ fontSize: 14.5 }}). List dài → mỗi render tạo object mới + không tái dùng CSS; font-size lẻ (14.5/12.5) làm theming bất khả thi. Đã có design tokens (var(--ink), var(--sale)) — nên nhất quán dùng class.
  • Affordance gây hiểu nhầm: nút + (add-mini, nova-product-card.tsx:110) trông như "thêm vào giỏ" nhưng aria-label="View product" & chỉ điều hướng. Đổi icon hoặc làm đúng hành vi.
  • Swatch dùng key={i} (productForm.tsx:99–109) & nút chọn thiếu aria-pressed. Thêm aria-pressed={selectedColor === color}.
  • Type không khớp: addToCart(productId: string) (cart.ts:97) nhưng gọi với product.id kiểu number (productForm.tsx:49) rồi Number(productId) lại. Chuẩn hóa kiểu id xuyên suốt definitions.ts.
